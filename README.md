# 祈福本地执行器（V9 双一键断点续跑版）

## V9.5.86 迟到场景弹窗接管修正版

- 场景图批量上传窗口由固定等待 10 秒改为最多等待 60 秒，并持续确认 iframe 内文件选择控件已经真正挂载；大量订单导致平台迟迟才打开窗口时，程序不会提前报错退出。
- 每次只接管最新的场景上传窗口，避免误用上一轮已隐藏的 iframe；若最终仍超时，保持“未选择、未上传”的安全断点，已经成功的供水或供灯批次不会重传。

- 微信原图拍摄时间出现明显断点时，程序会切断连续编号推断；补拍旧编号不会再被文件流水号误导成前段末尾的后续编号。
- 同一相机的低位编号使用上下两个严格原彩小框读取，完整业务前缀和编号必须唯一存在于当天 PDF 索引中；清晰可见编号不会再被低区分度的正文指纹排名否掉。
- 真实 8 月 28 日 13 张原图回放已确认 603–613、597、598；原来错误形成的 614、615 分别来自真实 597、598。

## V9.5.83 编号双证据复核版

- 自动编号不再只相信 OCR 票数或已经存在的数字文件名：清晰编号必须由多裁框 OCR 共识和当天 PDF 唯一编号索引共同确认；折叠、遮挡及推断编号再进入缺失 PDF 页正文指纹复核。
- 可见编号与文件名冲突、推断结果与 PDF 指纹冲突、PDF 匹配不唯一或相似度不足时安全停止并保留原文件，不按缺号或顺序强行放行。
- “重新核对编号”是独立只读检查：会复核未编号原图和现有数字照片，但不改名、不压缩、不上传、不修改平台。

## V9.5.82 微型编号带与场景识别修正版

- 针对 8 月 28 日新相机构图，编号识别会直接在上下两组右上微型编号带中复核，不再跟随被木架、神像和纸色污染的动态纸框。
- 微型编号必须同时命中当天 PDF 唯一编号集合，并由未二值化红通道和多个阈值形成同号共识；无法收敛时仍保留原图，不按缺号猜测。
- 供灯/供水场景新增低曝光灯阵和全宽黄色台阶结构证据；本地 PDF 页面指纹同时保留固定相机纸面候选，作为 OCR 未决时的离线复核路径。
- 继续保持 V9.5.81 的人工验证码登录路径，不恢复桌面机器接口入口。

## V9.5.81 人工验证码登录回退版

- 日常照片和 PDF 业务统一恢复为浏览器登录路径，不再在桌面界面提供机器接口或免验证码入口。
- 账号、密码可选择使用 Windows 当前用户 DPAPI 加密保存；出现验证码时程序只安全填入账号和密码，必须由本人在 Edge 输入验证码并点击登录，随后自动续跑原任务。
- 不删除 V9.5.76 的照片编号与场景识别修复，也不删除 V9.5.78 的上传接口精确回执、断点和上传防重能力。
- 机器接口代码仅保留为尚未启用的后续研发历史，不从本版桌面入口调用，也不会参与日常初始化或业务执行。

## V9.5.80 机器日清单只读联调版

- 高级工具的“检查接口/日清单”使用受限机器凭据直接读取所选照片业务日期的七类日清单，不进入后台登录页，因此不需要验证码。
- 日清单必须使用 `daily:plan:read`、`dryRun=true`，并通过日期、时区、七类分组、数量及匿名订单哈希复核；接口异常或契约不一致时安全停止。
- 本机仅保存日期、数量和匿名 SHA-256 检查回执，不保存客户正文、照片、账号、机器密钥或短期令牌。
- 本版只完成查询联调，尚未把上传、PDF 导出和状态变更切换为机器接口；现有浏览器流程保持不变，避免未经隔离验收的写操作触及生产。
- 保留 V9.5.79 机器凭据加密及此前所有业务回归。

## V9.5.79 机器接口认证接入版

- 原“自动登录”改称“浏览器辅助登录”，明确验证码仍需本人输入。机器接口只验证受限机器身份，不建立后台人员会话。

- 增量补跑若发现旧数字文件占错编号，会读取其纸面真实编号并执行安全归位，再补入真正的新照片；例如旧 `491.jpg` 实为 `495` 时，两张都能正确落位。

## 第一次使用

1. 双击 `启动祈福助手.cmd`。
2. 如果没有自动找到 NAS 目录，点击“选择目录”，选择包含 `@每日福单` 的 `@@圣堂祈福2026` 文件夹，或者直接选择 `@每日福单`。
3. 如需保存登录账号，展开“高级/故障工具”，点击“设置登录账号”并保存；出现验证码时本人在 Edge 输入并点击登录，程序随后自动继续。
4. 核对两个业务日期后，按实际需要点击“一键处理照片”或“一键处理 PDF”。两者互相独立。
5. 日常无需点击分步骤按钮。只有排查故障时才展开“高级/故障工具”。

V9.3.3 起，同一次使用期间所有按钮共享这一个专用 Edge。升级后第一次启动前，请先关闭旧版本残留的祈福专用 Edge 窗口；此后不要关闭该窗口，程序会一直复用。浏览器保持打开不等于后台保活，程序不会在任务结束后持续刷新网页。

用户点击“一键处理 PDF”即授权本次 PDF 闭环；只有 PDF 全部导出并校验通过后，程序才自动变更同一批订单状态，不再弹出第二次确认。

程序启动、切换业务日期或更换目录时，会自动初始化对应的本地文件、回执和线上状态。发现 PDF 后不会重复导出，也不会仅凭文件存在判定完成：“一键处理 PDF”会校验原凭据和线上清单后直接从未完成环节续跑。只有正式“供灯福单”和“牌位福单”两处待祈福均为0，才提示当天 PDF 工作完成。

## 每日 PDF 顺序

程序强制执行以下顺序，不能跳过：

1. 在正式“供灯福单”页精确查询 `[PDF 日期, PDF 日期 + 1天)` 的“待祈福”订单，并单独检查正式“牌位福单”页。
2. 保存不含客户姓名、祈愿正文等信息的订单清单。
3. 没有 PDF 时导出并校验；已有 PDF 时验证原凭据并跳过导出。
4. PDF、日期、数量和订单哈希全部一致后，自动把同一批订单改为“祈福中”。
5. 再次查询目标日期“待祈福”为0，并写入完成凭据。

上传、导出过程中的普通网页确认框由程序自动处理。程序不会在没有 PDF 校验凭据或订单哈希不一致的情况下修改订单状态。

## 按钮说明

- “一键处理照片”：自动读取当前回执并从下一未完成环节开始，依次完成处理编号、规格校验、福单上传、供水/供灯场景图上传、普通订单批量完成，以及无需场景图的牌位订单批量完成。每一步成功后都写入回执；中断后不会从头重做。

## 数据和安全

- 浏览器使用独立的本机专用会话。只有用户主动在“设置自动登录”中保存时，程序才会读取并填写由 Windows 当前用户 DPAPI 加密的凭据；账号密码和 Cookie 均不会写入日志、NAS、Git 或迁移包。
- 性能日志只记录阶段耗时、数量、重试和人工介入，不记录客户资料、订单正文、照片、账号、Cookie。
- 下载失败不会自动重复点击“导出”，防止重复消耗系统编号。
- 最终 PDF 不覆盖同名文件；发现冲突会停止。

## 照片安全规则

- 照片业务日期和 PDF 业务日期相互独立；程序不会因为“今天运行”就擅自更改业务日期。
- 已规范命名的福单按纯整数文件名上传；供灯场景图仅接受 `2.1.jpg/2.2.jpg`，供水场景图仅接受 `2.5.jpg/2.6.jpg`。
- 自动处理以 PDF 编号范围、照片数字、多锚点连续关系和明显纸张形状为证据；任一证据链不闭合就停止，不会猜号。
- 接近 4:3 的照片会自动处理为 1800×1350、JPEG 画质 90，并在必要时逐级压缩但不低于 82，确保不超过 1.5 MiB。不接近 4:3、需要主观裁剪或补黑边的照片仍停给人工处理。
- 发生崩溃或中断时，程序不会盲目重传同一批图片；先在线核对，再重新预检。
- 旧照片替换继续保留人工确认。

- 只对已有明确授权且状态为 failed/running 的照片断点自动续跑；普通启动和首次上传仍由用户点击照片主按钮触发。

# V9.5.8 上传状态自动接续说明

- 福单图上传中断后，不再因为线上已有匹配订单而要求人工确认。
- 自动同时查询目标日期的“福单已上传”和“福单未上传”：已上传大于0且未上传为0时，直接补写本地上传成功回执并进入场景图流程。
- 13张福单图可能匹配170条订单，两种计数分别保存，不要求相等。
- 只有线上同时存在已上传和未上传订单，或两边都为0无法证明结果时才安全停止。

# V9.5.7 初始化解耦修正说明

- 启动时照片本地预检优先，不再无条件进入 PDF 线上登录检查。
- 新业务日没有本地 PDF/校验凭据时，启动初始化直接解锁照片按钮；PDF 查询延迟到用户点击 PDF 主按钮。
- 本地已有 PDF 或历史处理凭据时仍自动进行线上复核，但未登录只快速等待 5 秒后退出，不再让界面卡住 10 分钟。
- 手动点击“重新检测 PDF”仍会执行线上检查；真正点击照片上传或 PDF 业务时保留正常登录等待。

# V9.5.6 福单上传修正说明

- 修复月份窗口“确定”按钮在共享 Edge 中卡住并于 30 秒后报 `locator.click timeout` 的问题。
- 兼容网页使用原生确认框或 Layui 确认层两种实现；确认框已被全局监听器接受时不再误判失败。
- 上传回执新增细分阶段，能区分文件选择、月份提交、上传确认和数量校验，便于断点诊断。
- 上传后仍必须取得与本批一致的系统返回数量，未取得可靠数量时停止，不把未知状态记成成功。

# V9.5.5 临时文件修正说明

- 照片处理时，原图不再在每日照片目录中改名为 `.prayer-*.original`。
- 原图先原子移动到自动化工作区的内部隔离目录，成品全部落盘后再清理；NAS 暂时占用时也不会污染每日照片目录。
- 处理回执新增 `quarantineDir` 与 `cleanupPending`，便于审计内部隔离文件是否已经清完。

# V9.5.4 照片识别修正说明

当日 PDF 全部导出并校验成功后，程序会确保同一 `M月D日` 目录内存在 `1` 文件夹，供保存当天回传原始照片。若启动或复核时检测到当天已有 PDF 但缺少 `1`，会自动补建；已有 `1` 文件夹及其中照片始终保留，不重建、不清空。

# V9.5.20 自适应纸张识别与缺图诊断说明

- PDF 按业务类型与文件内页码建立编号索引，避免增量红纸文件被错误插入黄纸/牌位顺序。
- 先定位红纸或黄纸矩形，再读取纸张右上角编号；场景图不再因为微信文件名被误当成福单图。
- 支持连续拍摄中的递增和递减编号片段，并以至少三个可靠锚点补齐中间弱 OCR 照片。
- 对 2026-08-13 已逐张复核的 43 张原图保存文件哈希证据：准确归并 35 张唯一福单、5 张重复照片、2 张供灯场景图和 1 张供水场景图；补发照片到齐后可直接通过一一对应校验。
- 原图和本地隔离目录位于不同盘符时，不再直接调用跨盘 `rename`；改为独占复制、刷盘、SHA-256 校验后删除源文件，失败时保持源文件并清理未完成副本，回滚也使用同一安全路径。
- 后续把供水照片补进同一目录时，程序只复用哈希一致的旧证据并识别新增文件，不会重新猜测已复核照片，也不会在缺图时修改 NAS 原图。

# V9.5.19 同日增量补单说明

- “当天已有 PDF”不再等同于当天永久结束；每次继续都会重新查询供灯、牌位和续费的线上待处理清单。
- 普通福单/牌位出现新单时，只导出当前新增待祈福订单，红纸、黄纸从当天现有最大序号继续；供水补单使用“供水2、供水3……”避免覆盖。
- 续费已有未处理订单和 PDF 时，按订单 ID 排除已覆盖记录，只为新增续费生成顺延编号 PDF。
- 原 PDF、原回执和原完成状态保持不变；每个增量批次单独保存清单、PDF 哈希和状态凭据，可断点续跑。
- 数量通知按同一天所有已成功纳入的普通批次累加，不会只显示最后一张补单。
