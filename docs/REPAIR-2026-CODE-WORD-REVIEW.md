## 原因及改动

检测器已经定位完整编号行，第一引擎两个边距读数一致，但第二引擎的单行分割可能空读或只有低分同号结果。原有红通道补读仍不满足要求时，该入口直接返回未确认。固定同一像素输入的对照表明，按整段代码读取能够恢复部分读数；不是调整 PDF 缺号集合或降低通过阈值。

[Tesseract 官方分割说明](https://tesseract-ocr.github.io/tessdoc/ImproveQuality.html#page-segmentation-method)区分单行模式 7 与单词模式 8；是否接入仍以本机实测为准。不能全量替换：本次对照也观察到模式 8 给正常读数新增错字，所以仅在原扫描完整、全部完整码一致、没有断尾/异常、第一引擎仍获双边距支持而第二引擎尚未确认时，追加一次模式 8 补查。

补查读取同一检测区域的两个原边距、固定灰度 96 高度、最多四个区域，完整保存 `segmentationReview`、原空读、所有相反码和置信值。它仍是原 Tesseract 引擎，不算第三引擎。新的相反码、尾号拆分或异常均继续扣留，不清除旧审核历史、不绕过正文/PDF/重复号检查。

显式恢复单行设置，防止补查影响下一张照片或 PDF。模型调用失败后也恢复；恢复本身失败则销毁该 worker 并报固定错误，不继续使用状态不明的实例。缓存校验同时核对补查完整性、恢复状态、配方和原裁框，不能凭修改后的成功标签续跑。
