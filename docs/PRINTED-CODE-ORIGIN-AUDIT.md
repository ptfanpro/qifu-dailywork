# 打印编号来源审计（只读线索，尚未修复/部署）

本次读取的是用户提供的迁移后端开发副本，不是线上运行进程；尚未证明该副本与当前生产源码完全一致。没有连接数据库、调用写接口、重导出 PDF 或修改后端。以下区分源码事实、推论和待验证项，不能据此把全部识别失败归为同一原因。

## 编号图片本身

后端 `BlessingServiceImpl.showNumber` 将编号用 Java2D 绘入 `100 × 15` 像素位图，再按 `100 × 15` PDF 点放置；`showTabletNumber` 同样使用该尺寸。普通编号字体为 15 像素，竖版为 13 像素，牌位编号为 11 像素。编号不是直接写入 PDF 的向量文字。

这是原始打印码分辨率有限的源码证据；拍远、模糊或反光可能进一步减少有效像素。它不是所有未识别照片的归因证明，也不能通过放大裁图凭空恢复缺失笔画。是否改善打印字号/位置/矢量输出或新增机器可读标识，需单独验证、确认和部署，不能在本地识别修复中偷偷改动现有打印件。

另对一个历史日期的四份真实 PDF 各取首个物理页：直接解析图像对象及页面坐标，并渲染完整页面核对，确实存在 `100 × 15` 像素、显示为 `100 × 15` 点的右上编号图像。四页共五个该尺寸对象，其中一页在相同坐标叠放两个字节相同的编号图像，与源码重复调用一致。相同图像不得当成两份独立编号证据。所有源文件哈希前后不变。这个检查只涉及四个首页，不能推广为全历史模板均一致，也没有确认照片识别已经改善。

另作四份不同字节原始编号图像的本地双引擎读取：原尺寸及固定留白/96 高度两种输入，共 16 份读数均与所查看完整页上的码一致。没有向引擎提供月份或尾号答案；原始尺寸下有一份 Tesseract 虽读对但自评分为 0，不能把它称为高置信读数。固定留白后的四份第二引擎自评分为 88–91。这个约 1.56 秒的读取试验不含 PDF 提取、照片处理或订单核对，不是生产提速或识别修复结果。后续若采用原图像路径，必须验证物理页坐标、裁剪/遮挡/重复对象及完整码证据，不能把不可见对象当打印内容。

## 编号月份并非业务日期

后端 `BlessingOrderMapper.updateRQcodeNumber` 用数据库 `now()` 的 `%y%c` 生成编号月份前缀；跨月时编号计数从 1 开始。完整编号由 `years-app_number-number` 拼成。用户选择的标题日期用于打印标题，并不参与这个编号月份的生成。

`saveRQcode` 同时保存完整编号、租户及该页订单 ID 列表（`ListPage.code` 的分组结果）。重新导出会再次分配编号；实际打印页是一次导出修订的身份，不能把末号当永久订单号。这里只确认开发副本存在该映射；没有读取线上表，也没有证明其保留期、历史完整性或可用只读接口。

本地当前存在以下不同假设：

- `runner.mjs` 在两处照片计划入口按照片业务日期构造 `expectedPrefix`。
- `indexPdfCodes` 按该前缀对候选排序/筛选；照片的严格复核也继承同一前缀。
- `PrayerSite.uploadBlessingBatchFromStaged` 根据传入的业务日期构造上传月份。

因此“上月业务、本月重新打印”的场景存在明确的日期命名空间不一致风险。需以真实导出凭据及合成跨月测试复现，不能仅为通过某张照片而放宽前缀、删除相反观察或硬改日期。用户的照片默认昨天、PDF 默认今天及手动日期选择保持不变。

对已完成年度基线保存的 224 个日期、4,587 页 PDF 观察作了一次只读重解析（没有新增 OCR）。4,581 页有可解析的完整字符串，1,139 页的保留观察中出现过其他前缀字符串，但没有一页具备两个引擎高分同读相同其他前缀的证据。这些可能只是旧 OCR 噪声，不得报成 1,139 个跨月错误；原记录又经旧前缀过滤及数量截断，因此也不能凭未发现一致证据就排除跨月风险。原报告、图片、PDF 与绑定全部未改。

## 后续修复约束

1. 分开业务日期、打印修订/完整编号、上传月份；场景图及线上订单筛选仍归原业务日期。
2. 打印月份只能由与当前 PDF 文件内容哈希、物理页及完整编号绑定的证据取得，不能从执行日、旧文件名、月份多数票或尾号推算。
3. 跨月可能出现两个不同完整编号共用同一末号；当前纯数字成品命名不能直接表达这种冲突。必须显式保留并设计分批/修订范围，不能覆盖目标或混用上传月份。
4. 有条件取得原始逐页订单映射时，只读验证租户、完整编号、页订单集合与 PDF 修订；不得把上传接口当查询接口，不能新建管理员会话、绕过验证码或直接读取数据库凭据。
5. 先增加同月、跨月重打印、跨年、相同末号、混合月份、源替换及上传月份/业务日期独立的失败优先回归，再接入生产调用链。

现有正文保护明确 `bindingVerified=false`，不能用上述后端映射“应该存在”的推论将其改成已验证。原修订/页面集合缺失时仍需保留未决。该审计不是已经完成跨月兼容或逐页绑定的发布说明。
