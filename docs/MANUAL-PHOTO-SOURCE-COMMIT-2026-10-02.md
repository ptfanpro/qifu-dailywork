# 原目录照片压缩恢复（开发修复 2026-10-02.1）

旧的原目录事务先把原图 rename 到本机隔离目录；跨盘时复制后 unlink 原图，再创建成品。Windows 的删除共享权限同时控制删除和改名。兼容读写但不允许删除的读取句柄会使原事务报 EBUSY。为避免此故障，4aa6108 改为仅处理本机镜像，原目录不再改变。这解释了后续每天原照片仍是大图的行为变化。

历史报错没有保留持有句柄的进程信息，不能指认同步客户端或 libvips 为唯一责任方。本次只读探测时所选原文件可以独占读取。已通过独立 PowerShell 进程保持真实 FileShare.ReadWrite 读取句柄，复现旧 rename 失败；相同句柄保持打开时，新保存方法成功。

新流程保留本机编码与上传副本，把已验证的同名 JPG 写回原目录：取得 ReadWrite / FileShare.Read 句柄，排除其他写入、删除或替换，核对原图 SHA-256、完整备份并刷盘，写成品并校验。写入异常时仍在同一受保护句柄内恢复原数据；硬性写入锁有限重试后失败。逐文件状态和备份保存在本机，未验证完成不声明原目录压缩完成。PNG/JPEG 改扩展名沿用原来的有备份事务，仍需文件可改名。

镜像来源哈希因写回变化时，建立受来源日期、原目录、文件哈希约束的本机别名，继续复用原来的压缩字节和上传回执。新增或外部替换照片使用新的镜像；重复启动不再压缩已有成品。

回归覆盖原目录尺寸和字节上限、与上传副本完全一致、原图备份、重复启动、真实 Windows 共享读取锁、禁止写入锁、释放锁后续跑、同步替换拒绝、PNG 转换、旧线上完成状态下原目录仍可处理，以及新备份保留和中断备份禁止清理。完整核心和 Windows 回归用于开发验证，不替代实际业务验收。
