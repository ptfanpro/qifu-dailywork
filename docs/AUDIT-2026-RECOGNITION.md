## 已定位的根因和本分支修正

| 风险 | 原设计的问题 | 本分支处理 | 验证方式 |
| --- | --- | --- | --- |
| PDF 基准错误 | 看不清的后续批次仅凭前段连续和页数补出尾号 | 禁止无锚点尾段猜号；禁止仅因剩一个缺号给整份未读 PDF 定号 | 不可读尾段、跨 PDF 缺口负例 |
| 年份当编号 | 重复的牌位年份也可能参与最优连续序列计算 | 带 OCR 观察的页面必须有业务前缀证据才能作序列锚点 | 三页重复年份负例 |
| 推断覆盖实读 | 序列优化可以重写页面上多框读出的完整编号 | 页面完整编号优先；保留真实导出缺口和四位尾号 | 有缺口的明确编号、四位尾号反例 |
| 月份/紧连编号 | 前缀限定三位；扩大到四位又可能贪婪吞掉三位前缀后的中间码 | 精确业务前缀优先，再做有边界的模糊解析 | 全年 12 个月 × 多种尾号/分隔符 |
| 文件名特例 | 某日仅凭一组普通文件名就套用人工编号 | 移除无哈希的人工赋号特例；原有哈希限定证据单独保留 | 防止特例回流的规则测试 |
| 纠错制造错号 | 已经完整的 90—94 仍被“离群修复”改成 95、91—94 | 已完整且唯一的连续编号集禁止再次挪动端点 | 实际历史反例的脱敏重放 |
| PDF 编号区留白 | 窄框内大量留白把字符压小，118/119 的中间码漏读 | 保留原路径，并增加仅针对编号行的去留白加边距读取 | 实际裁图、合成图像像素保全测试 |
| 备用证据污染 | WinRT 仅读出前缀/年份，也可覆盖原引擎观察并标 100% | 只接收完整业务码；保留原始观察，不伪造 WinRT 数值置信度 | 前缀、年份、歧义、空结果负例 |
| 陈旧编号缓存 | 同一天就复用 PDF 编号集，未核验 PDF 及识别规则版本 | 绑定业务日期、PDF 名称/内容哈希、识别源码指纹；过期索引重建，不删除上传回执 | 同名同大小替换、删 PDF、日期变化、规则升级 |
| 识别后文件变化 | 备份的是当前照片，但并未证明它就是之前识别的那张 | 计划绑定原图哈希，处理备份副本，移动前后再核验；回滚被占用时保留隔离原图 | 同名同大小替换、备份中替换、回滚占位模拟 |
| 单文件影响整批 | Windows OCR 一个文件异常就使整个子进程失败 | 每文件独立错误结果，保留其他成功结果并释放位图 | 有效—损坏—有效三文件实测 |
| 缺证据误报错号 | 无可用指纹或区分度不足，被标为已确认编号冲突 | 新提议保持未决、不赋号；只阻断真正冲突，其他确认项可继续 | 无指纹、低区分度与真实冲突正反例 |
| 独立证据被降级 | 两个引擎确认后的新结果仍继承旧提议单票数量，被场景或指纹兜底否决 | 明确识别独立双引擎完整码证据，保留其优先级 | 单票遗留值、烛光背景、重复同引擎反例 |
| 测试不隔离 | UI 测试加载真实设置并进入窗口消息循环 | 临时配置目录、禁止显示窗口、禁止真实初始化 | Windows UI 状态测试 |

PDF 窄编号区也加入现有本地便携识别引擎，读取原始完整编号证据；没有靠放开安全校验来“通过”。

没有内容哈希的其他历史批次捷径也已禁用，不能因为文件名和数量相同就视为人工已确认。跨盘测试脚本改为仅创建、清理自己新建的临时子目录，不再删除传入目录。回滚时若同步程序替换了刚创建的目标文件，也必须保留该文件，不能按原计划删除外部新版本。

## 核心设计仍需完成的重构

1. 文字定位和字符识别分开。现有便携模型主要是行识别器，位置兜底最多遍历 874 个窄框；移动拍摄构图后要付出很高的扫描成本。实验性文字检测器只在 `tests/experiments` 使用，未接入默认执行器。
2. 独立记录“读出了什么”和“是否属于本日 PDF”。不能先用可能错误的 PDF 编号集过滤掉原始识别证据，再把结果叫作“照片读不出来”。
3. 同引擎不同裁框不是两个独立引擎。实验报告同时保留两个引擎的观察，尚未确认的样本不能计为成功。
4. 场景判断不能只追逐全图亮度、暖色比例和日期特定阈值。需要前景纸张、编号、灯阵/供水结构的统一证据，并同时回放真实福单反例，避免把烛光前的纸张当场景。
5. 单张未决、引擎不可用、源文件缺失、PDF 基准冲突应是不同状态；确认过的独立任务可继续，未决项不能被错误完成。
6. 版本管理保留代码历史，但不能替代真实数据验收。旧测试曾把“猜出连续尾号”当正确结果；所以测试本身也必须接受业务规则审计。
7. 照片路径中的旧 WinRT 严格兜底仍含“窄框数字 + 本日候选集”规则；它不等于独立双引擎完整码。PDF 路径的假置信度和覆盖问题已修，不能据此声称所有照片兜底路径已经重构。
8. 历史材料可能混有重新导出前后的两套编号。例如 4 月 14 日目录存在两组历史福单数字名，而当前 PDF 仅 14 页。差异必须区分旧副本、真实缺图、重新编号和识别错误，不能把所有集合差异都报成 OCR 错误。

## 发布门槛（尚未满足）

- 原有与新增单元测试、隔离 Windows 回归均通过；不把跳过的测试写成通过。
- 全部可用历史照片完成冷启动回放，记录未决、错配、缺原件、人工证据命中及耗时，逐项解释。
- 修正前后的结果按同一输入哈希、同一规则/模型快照比较；新错配必须为 0。不能借放宽判断来降低未决数量。
- 对明显失败样本加入脱敏回归及独立留出验证；新相机角度、纸色、月份、编号长度和增量补图也应覆盖。
- 不以离线识别通过宣称线上上传、回执和闭环已验收。真实业务连续三次稳定后才考虑更新默认桌面入口。

不能保证未来所有照片都可自动识别，更不能承诺永远零 bug。目标是减少未决、禁止错配静默通过，让每个故障有证据、有回归、能追溯且可安全恢复。

## 实验模型来源

仅下载公开模型，不向网络发送业务材料。文字检测模型固定使用 [RapidAI 发布清单](https://github.com/RapidAI/RapidOCR/blob/v3.9.2/python/rapidocr/default_models.yaml) 中的 PP-OCRv4 mobile，SHA-256 为 `d2a7720d45a54257208b1e13e36a8479894cb74155a5efe29462512d42f49da9`。预处理参考 [PaddleOCR 2.7 检测流程](https://github.com/PaddlePaddle/PaddleOCR/blob/release/2.7/tools/infer/predict_det.py)。实验的连通域候选提取不是官方多边形后处理的等价实现；必须实测，不因引入模型就宣布可靠。
