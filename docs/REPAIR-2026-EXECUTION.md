## 第一批代码修复

1. **编号定位：产品改动 + 回归 + 整日实图对照。** 把已独立验证的全文字行检测原语接入照片入口，先读取内容定位的行，再进入旧固定网格。两种 OCR 引擎均检查每个候选行的两种留边；完整相反码、不同年月、缺字、未完成读取仍不得通过。没有检测到号码不等于没有纸张，检测失败不等于场景。正文否决、PDF 唯一页和重复号保护仍保留。
2. **重新核对统一入口。** 已编号照片不再单独走 Windows 固定条带读取，复用新照片的内容检测、双引擎和原始观察保留。文件名只作为待核对声称，不会因其已经是数字就自动信任。新增回归在修改前失败、修改后通过。
3. **未匹配不等于缺照片。** 照片清单、上传日志、分批完成卡片和旧断点显示区分未匹配 PDF 页面与目录内待识别照片；仍保留旧计数字段兼容状态及全部完成门槛，不以改提示掩盖失败。
4. **正文复核缓存。** 在本机工作目录缓存四视图读取观察，键绑定图像字节、完整识别源码指纹和模型哈希，校验缓存内容哈希。损坏/失败/截断/身份缺失不复用，缓存不可写不改变识别证据。每次重新建立当前 PDF 页面集合并检查归属，不缓存“已确认订单”的决策，也不把正文写入性能日志。
