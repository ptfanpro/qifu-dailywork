## 已确认的缺陷

`indexPdfCodes` 的现有候选并非完整 OCR 观察：Paddle 先经过分数及预期前缀筛选，全部候选再排序后截为前八项；Windows 补查也在写入前限定前缀和可接受尾号。后续审计无法据此证明没有低分或跨月份相反观察。打印月份来自后端导出时刻，并不一定等于照片业务月份；本轮不据此猜测哪份历史订单发生跨月。

## 修改范围

- 增加独立 `printCodeEvidence`，保存每次本地编号读取的规范化完整码及空白/不完整尾号/失败标记，无预期业务前缀入参，无候选排序或数量截断。
- 记录绑定实际读入的 PDF SHA-256、物理页、实际 OCR 输入 PNG SHA-256、引擎、布局、原始数值置信度和量纲。可用的 Paddle 模型哈希一并保存；记录校验和仅检测变化，不是签名或 OCR 正确性证明。
- Windows 保留空读及错误结果通道；未返回结果不伪造成功。Paddle 原始/去空白视图分别记录，单个视图失败不吞掉其他视图。Tesseract 异常仍中止，本地留下 `complete:false` 的私有部分记录，稀疏模式在退出前恢复。
- 新通道不保存客户正文、原始 OCR 全文或异常原文；完整码仍属本机业务证据，不进入 Git。私有计划的旧候选选择、业务日期、上传月份和上传权限没有被新通道替换。
- 新模块纳入识别源码指纹，旧缓存不能冒充新版观察。未实现可信逐页订单绑定、混合打印月份上传或全部场景识别。
