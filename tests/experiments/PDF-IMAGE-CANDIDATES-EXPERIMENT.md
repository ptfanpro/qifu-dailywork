# PDF 原始编号位图：可见性校验试验（未接入产品）

## 目的和边界

后端开发副本及四页真实 PDF 已确认存在 100×15 像素编号位图。直接读取它可能避免先渲染整页、再放大裁切引入的额外变形；但 PDF 内部存在图像对象，不代表用户打印页上能看见它。

新增 `pdf-image-candidates.mjs` 只接收 PDF 字节，不接收业务日期、预期月份、尾号、照片或历史文件名。使用本机 pdf.js 和 canvas；没有网络、改名、上传、状态变更调用，也没有接入正式计划器。

当前只支持窄范围：100×15 像素、不透明、正向、不旋转、不缩放、整数坐标且完整位于物理页内的图像。跟踪保存/恢复、变换、Form 及重复图像位置；不支持的合成组/注释上下文不出候选。最终页面以原生比例渲染，候选原始 RGB 与同位置最终页面 RGB 必须逐字节一致，不能仅检查边界框相交或看到几个黑点。

图像、PNG、最终页像素、PDF 内容哈希及物理页码均保留身份。同页同位置相同像素的叠放图像只计一次；不同物理页不可合并。候选不带自动推算的编号，`orderBindingVerified=false`、`mayAuthorizeUpload=false`。依赖尚未解码时最多等待 5 秒，失败保留拒绝原因，不能当图像不存在。

这不是通用 PDF 图像提取器，也不是完整字符保证：原位图生成时就截断的笔画、空白间隙中的断号、打印修订/逐页订单对应仍需额外证据。看得见的位图并不自动变成正确订单。暂不对不适用页面放宽精确像素比较或去掉边界检查。

## 新增六项合成回归

覆盖正常可见图片及输入不可变、隐藏/裁剪/遮挡/透明/旋转拒绝、重复叠放去重与跨页独立、两个不同码同时保留、旧图被新图盖住/部分越界，以及等待回调期间输入替换失败。

新模块建立前测试因缺少模块而失败，这是新能力的测试先行，不是六个线上故障已被复现或修好的证明。实现后发现 pdf.js 的渲染 intent 和 operator-list intent 可以分别解码图像；增加有界等待后，通过六项实际渲染测试。一个后来添加的越界样本起初同时覆盖了正常样本；保持正确拒绝逻辑，将测试布局分离后验证两项各自行为，没有放宽产品判断。

六项已加入普通测试入口。运行：

```text
node --test tests/experiments/pdf-image-candidates-regression.mjs
```

## 两个历史日期的 99 页实测

固定读取器在八份真实 PDF 的 99 个物理页上只读执行。不是再跑一次照片全流程，也不是新一轮全年回放。

- 97 页得到与最终页原生像素完全一致的原始图像；两页不适用严格提取路径。
- 每个候选仅采用事先固定的白边 12 像素、总高度 96 输入，分别交给本机 Paddle 和 Tesseract PSM 7。没有向引擎提供月份或尾号。
- 69 页两个引擎完整码相同，且达到试验预设分数（Paddle ≥0.85、Tesseract ≥50）。另 25 页完整读数相同但分数不足，3 页读数不同或不完整；不降阈值制造通过。
- 69 项与对应冻结计划中的同 PDF 哈希、物理页编号没有差异。这是与已有记录的一致性，不是 69 个修复，也不是独立正确率。
- 提取与读取约 40.815 秒，不含复核脚本、开发测试和完整照片流程，不能直接比较每日处理耗时。

另一个脚本重新提取全部 99 页，逐项验证候选 RGB/PNG 哈希、位置、重复计数、拒绝项、原件哈希及页面集合，并根据保存读数重算 69/25/3 分组；没有再次 OCR。一次验证脚本因假定计划文件名而失败，改用实际的私有计划文件后完成。原报告未被改写。

实际照片、PDF、原始位图、读数、逐页记录及运行计时全部只存本机专用 TEMP，禁止提交或打包。

## 尚未满足的接入条件

需继续验证其他日期/模板、竖版与页面裁剪、原位图自身断字、与现有 PDF 观察的冲突保留、打印修订及逐页订单绑定。不能用内部不可见对象恢复一个打印页上不存在的码，不能通过只挑好页、忽略未决或依赖连续尾号宣布修复。

当前正式场景语义反例仍有三项失败；本试验不替代它们，产品源码、版本号和固定入口均未改动。
