# Source-bound positioned-field / original-code join

This candidate is not an annual or online acceptance and is not a release.
It adds an actual assignment path for a narrow previously unresolved case,
without changing the existing complete-code or long-field thresholds.

## What was incomplete

The prior collector read current body positions and all-page geometry but never
used those observations to corroborate an unresolved original full code. Short
names shared with another PDF page could not satisfy the older rule requiring
two individually page-specific whole fields of at least four Han characters.
Two real tablet photos therefore remained unresolved despite a consistent
original full code and a distinct located combination of name and tablet text.

## New conjunction (all conditions required)

1. The original code reader must still satisfy its complete two-engine scan,
   two original high-confidence crop and unique full-code/index requirements.
   Any credible contrary full code or prefix remains a veto. The original raw
   observations and failed first-pass audit are preserved, never rewritten.
2. Current full-PDF body assessment must have no contrary/ambiguous content.
   An earlier failed review is not cleared by this new rule.
3. A fresh process-local pinned-worker report must bind the complete physical
   PDF/page set, original photo bytes, exact positioned views, rendered-image
   dimensions and extracted PDF fields. Serialized or modified reports cannot
   authorize a join. Changed text or physical-page evidence cannot be borrowed.
4. At least two distinct whole 3–40-Han fields must be observed in both padding
   views at the same detector locations. Repeated occurrences, disjoint crop
   snippets, multiline joins and nested substrings do not supply two fields.
5. Matched field rectangles must lie inside observed geometry-support hulls
   on both images and overlap after projection by at least 0.5 IoU. All
   coordinates use the worker image size, not the original OCR image size.
6. The complete field combination must occur on only one physical page in the
   full corpus, counting both extracted fields and visible OCR fields, including
   occurrences within longer/multiline fields. That page must be the original
   independently observed full-code target. No highest-score or missing-slot
   inference is used.
7. The two supporting original code crops must lie inside the same proposed
   printed-content envelope. This rejects a code on a neighbouring sheet; it
   does NOT claim a measured physical-paper/foreground boundary. Those flags
   remain false, and geometry never clears contradictory digits.
8. Rehash all photo/PDF sources after the body and geometry work. The existing
   live code/body authorization, post-plan source/index check, JPEG transaction
   and exact transformation-receipt/restart gates remain in force. This proves
   local page correspondence only, not online order/upload/batch completion.

Positioned text stays private/process-local. Persisted joins carry hashes,
counts, policy and overlap evidence, not customer names or body strings. Lazy
geometry remains restricted to residual eligible candidates; initialization,
fixed launcher, default business dates and manual CAPTCHA are unchanged.

## Remaining gates

The third photo still has a credible conflicting prefix and remains excluded;
the day is NOT marked complete (`ready=false`). Other hard days, the final
frozen annual replay, exact order correspondence, clean-PC portability and
online acceptance are still unfinished. A single improved day must not be
presented as full-year success or a guarantee against future bugs.

The release command now requires the actual positioned join/restart integration
after runtime-asset verification; omission/failure prevents code-gate success.
Code gates alone explicitly never grant release acceptance.
