# 前缀异读与当前 PDF 正文联合核验

候选源码指纹：`ee54b02dc9c0f4ca36b70969d28a8a9c37c38946aa5e53c440151475da398ca8`。
基线提交 `041b4bb`。仍为 `9.6.8-rc.2`，不是发布版或全年验收结论。

## 原因和范围

真实难例存在“原始两张裁图都把月份前缀的一位读错，但末尾编号稳定”的情况。
原来的备用中文模型在同样的两张原图裁剪中读到了完整正确编码，一张得分未达到
原有联合规则的要求。不能靠 PDF 缺号补答案，也不能降低全局阈值。

新增路径要求：原始双引擎扫描完整；同一个检测区域两张原图高分末号相同，
差异仅限前缀一位替换；可信的其它读数不能出现不同末号；原始两个引擎若均在
两张裁图支持另一完整编码，仍否决。V4 必须在两张原图裁剪读到同一完整目标码，
再按需加载固定哈希的本地 V5 大型模型，在两张完全相同的原图裁剪中以原来的
0.85 得分门槛读到同一码。V4/V5 不被当成独立引擎的多数票。

这只是候选编码，仍必须与全部当前 PDF 的至少两处独特完整长字段共同核验。
此新路径不使用短字段或位置几何兜底，不更改末号，不使用文件名、剩余空位、
拍摄顺序补号。原始读数、V4 读数和新 V5 读数分别保留并绑定源图和旧审计。
反序列化、篡改或失败的补充读数没有运行时授权。旧规则和独立已确认项不变。

大型模型总替换已经被否决：18 张/36 个原图裁剪中仍有稳定错号；另一项全墨迹
收边试验虽改善一张，但把原本正确的 194 稳定误读为 184，未接入产品。
这两个实验不能充当新识别准确率证明。
