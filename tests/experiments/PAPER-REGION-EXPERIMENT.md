# 前景区域定位试验（未接入产品）

目的：将候选纸张区域与整图灯光背景分开测量。它不改变正式编号、场景上传、正文否决或任何既有冲突。

固定流程：EXIF 旋正 RGB → 最长边 1280 的 Lab 三通道 → Canny 50/150、3×3 闭操作 → 轮廓/凸包的 2% 多边形近似 → 凸四边形提议。只保留面积占比 1%–85%、最短边 24 像素、边长比不超过 4 且不贴图片边界的提议；近乎重合的四角合并来源，嵌套纸/板不得仅按重叠面积合并。64 个提议或 20,000 个轮廓预算超限明确失败，不只留下前几个。

这些是首次实图前固定的试验参数，不是校准过的识别置信门槛。算法原语参考 [OpenCV 轮廓特征](https://docs.opencv.org/4.13.0/dc/dcf/tutorial_js_contour_features.html) 和 [Canny 文档](https://docs.opencv.org/4.13.0/dd/d1a/group__imgproc__feature.html)。凸包会填补凹陷/断边，所以不能把它称为完整纸张边界；矩形也可能是木架、背景牌匾、桌面或画面内部的一张卡片。

每个提议均做透视裁图并送入上一轮同一固定 CLIP 角色模型，两视图、四类别描述和权重保持不变。**所有提议均测量**，不按历史编号、人工坐标、PDF 目标或正确类别选择。两视图纸张首选仅为候选，不证明前景，不证明照片应是福单，更不证明订单归属；同一照片上有背景纸张与前景水碗时尤其不能直接分流。

明确命令：

```text
python -B tests/experiments/paper-region-geometry-tests.py
node tests/experiments/paper-region-replay.mjs PRIVATE_ROOT PYTHON ISOLATED_CV_DIR CLIP_MODEL_DIR FROZEN_RUNTIME YYYY-MM-DD [...]
```

OpenCV 来自已验证的独立本机 TEMP 依赖；不安装到全局或便携产品。Python 测试必须显式设置该进程的 `PYTHONPATH`，缺依赖失败，不静默跳过。像素管道只接收 PNG 数据和请求序号，不接收原图路径、客户正文、参考标签或目标编号；逐文件异常单列。角色模型在本机执行，无图片网络请求。

八个生成图/协议测试覆盖角点重复与反向顺序、同色背景连接支架、非纸矩形不能验证纸张、缩放回投、透视裁图、嵌套框、预算和非法图、真实 Python 管道的坏输入—好输入隔离及大图传输。初始仅轮廓方法在边框被支架打断的生成图上失败，保留该正例后增加凸包**提议**路径通过；不是修好了真实遮挡纸张的证明。

首轮在第 95 张原图前因试验管道限制停止：有效 4000×3000 图片转为 PNG 后约 22.8 MB、JSON 约 30.4 MB，超出旧 20/30 MB 上限。新增生成的 12 MP 随机图先复现请求 ID 丢失的失败，再将编码边界与原 30 MP 像素预算对齐。失败的 94 张逐图证据与旧快照保留，重跑另存新轮次；不称原照片损坏，不把它归为已部署软件的故障，不将重复读数加成独立样本。

结果、裁图和原件哈希仅保存于专用私有 TEMP。实图前冻结脚本，版本记录包含源码、CV 二进制、CLIP 权重与描述哈希。原件前后重哈希，每个完整日期的全部库存图均处理；汇总需从逐图记录独立重算。它不执行 OCR/编号、不操作浏览器、不改原件。新旧冷回放、场景语义三项已知失败和完整打印修订绑定的发布门槛继续保留。
