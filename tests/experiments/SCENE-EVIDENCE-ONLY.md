## 隔离包检查发现的额外边界问题

`4298643` 归档快照源指纹为 `c0251dd8d19041d18caa38d92881933cfe7f1be2582a8a69c108266c25de909f`。首轮工程启动器没有设置已安装依赖的 `NODE_PATH`，加载 `sharp` 即失败（0.244 秒）；包装命令还错误展开了退出码，故以保存的 `passed=false` 为准，绝不把外层退出 0 当通过。原报告保留。重跑使用明确依赖目录和脚本内退出码传递，不改系统执行策略。

第二轮实际通过场景反例、便携运行时（51.929 秒）和位置联合判定（24 断言、11 类拒绝、4 次重启，9.820 秒），随后在完整 Windows 套件中的审计路径回归失败，总计 80.384 秒。

原因：审计工具只要求证据目录在 TEMP 下，而测试用当前工作目录代替程序源码目录。源码通常在工作区，测试碰巧通过；隔离包也在 TEMP 时，程序目录就会被错误允许作为证据输出。修复按模块自身位置确定应用根，明确拒绝应用根及其子目录，仍允许独立私有证据目录。新增迁移到 TEMP 的真实模块副本用例先失败，再修正；不删除原失败断言、不放宽隐私边界。完整普通回归 238 项、0 失败/跳过。修正后统一隔离包检查尚待重新执行，不能沿用前述通过项宣布全套完成。
