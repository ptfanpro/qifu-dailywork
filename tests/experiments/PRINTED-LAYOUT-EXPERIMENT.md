# 印刷版式定位试验：仅离线几何提议

问题来源：颜色四边形会漏掉纸面上沿/编号，局部 CLIP 也把佛像和屋顶判作纸张。此试验从当前日期全部 PDF 的外周印刷特征寻找几何对应，而不是给区域模型更换描述或调亮度阈值。

与已有 `body-feature-probe.py` 不同：不比较正文相似度、不选“最像的订单页”、不赋号。共用花边恰好能支持版式定位，却**不能支持页面身份**。当前 PDF 可能不是原打印修订；成功投影不构成修订、完整编号、前景主体或订单绑定证明。

## 固定假设

- PDF 全页最长边 1800 像素；照片先按 EXIF 旋正，再等比缩至最长边不超过 1800。原件只读，派生 PNG 保存在本机专用 TEMP。
- PDF 外周 18% 带内提取 SIFT；模板最多 6000、照片最多 10000 特征，contrast .02。照片固定 CLAHE 2/8×8。
- BF L2 双近邻比值 .65，目标特征去重，RANSAC 4 像素/4000 次。至少 10 个内点且占匹配一半。
- 内点必须覆盖四象限、两轴跨度各 .6、凸包面积 .25。仅在一块印章或局部正文密集匹配不算完整版式提议。
- 投影四边形须有限、同向凸、无投影极点、全部位于照片内；最大内点重投影误差不超过 6 像素。不得把越界纸面裁到画面边缘后冒充完整。
- 对每张照片比较当天全部 PDF 页，保留每个页面的匹配数量/失败原因。不会按历史号、缺号或人工答案选页、选框。多个 PDF 页可能给同一纸面重复提议，数量不能当成识别照片数。

这些是开始真实照片前固定的试验参数，不是经过准确率校准的生产阈值。完整纸面边界或编号范围仍必须另行验证；纸面为场景背景的情况也不能仅凭提议自动转成福单。

## 运行与证据

```text
PYTHON -B tests/experiments/printed-layout-regions-tests.py
NODE tests/experiments/printed-layout-replay.mjs PRIVATE_ROOT PYTHON ISOLATED_CV_DIR YYYY-MM-DD [...]
```

运行 Python 测试时，仅本进程 `PYTHONPATH` 指向已校验的隔离 OpenCV 4.13.0.92 目录。不安装全局依赖，不下载模型。七项显式测试覆盖透视完整页、局部标志、正文局部粘贴、空图、镜像/越界、像素格式及实际子进程 PNG 哈希/协议；不在普通 Node 套件中，结果必须单列。

Node 入口记录源码/运行库指纹，在首次读取真实资料前复制三个试验脚本至新的私有轮次。Python 工作者只读该轮次中的派生、哈希验证过的 PNG，不读取业务路径、文字层、历史标签或 OCR 目标。完整逐图/页身份和原件哈希在 Node 侧核对；末尾复验全部原件及冻结脚本。失败报告和部分结果保留，不覆盖以前的轮次，不自动重试。

所有 `paperVerified`、`foregroundVerified`、`physicalCodeExtentVerified`、`bindingVerified`、`mayAssignNumber`、`mayClearCodeConflict`、`mayUploadScene` 均为 false。`candidate=true` 只表示几何提议。没有通过此工具清除产品未决、改名或上传的入口。

首轮真实对照为三个完整日期的 55 张照片，2026-09-09 16:34 启动，尚未完成时不得写成验收通过。首次启动在准备真实材料前遇到 sharp 禁止导出 `package.json` 的错误；改为解析公开模块入口并记录 `sharp.versions` 后重新启动。该故障仅属新诊断工具，不是现用软件识别缺陷；没有覆盖失败的实图结果（当时尚未产生）。

性能也必须记录：BF 比对全部页面成本较高，首张照片 13 页比对耗时约 29 秒，另有模板特征准备成本。不能把这条试验直接放到每天的启动初始化里，不能在未完成的轮次中替换匹配器或减少候选页数来改变实验条件。

## 2026-09-09 17:21 完成后复核

原固定轮次于 17:05 正常结束，55 张照片 / 45 个 PDF 页、62 个逐页几何提议，分布在 22 张照片；0 读取异常、所有原件及派生 PNG 哈希未变，冻结脚本未变。总报告时间 1866.023 秒，已含模板准备/匹配；不得再叠加逐图或 worker 时间。三天分别为 3/17、10/19、9/19 张有候选，不能把 62 个重叠提议算成 62 张识别成功。

全部 55 张完整派生灰度图及 22 张上的全部提议已人工查看，未向算法传入观察结论。候选大致跟随纸面，包含可见上沿编号；多张下沿被灯焰/碗遮挡，投影边界不是物理完整范围证明。此前颜色轮廓只取到正文、把编号留在框外的一张供水福单，此次五个版式提议覆盖了上沿。没有在十张历史场景参考中提出整页候选，亦未重复此前屋顶假纸张；**无码/无几何候选不是场景类别确认**。有的水景参考含近景模糊纸张，历史角色标签不是真值。

仍有 23 张历史福单参考没有候选，包括此前人工已看清编号的两张正常纸张。保存的全页比较显示：一张对多个横版页面已有 122–149 个内点，却只覆盖三个象限；另一张对全部四个竖版页面有 286–305 个内点，纵向跨度约 .91，但横向约 .53，未达到按 PDF 画布计算的 .6。它们分别提示遮挡/空白版面与全页空间要求的冲突；并非都没有检测到印刷特征，更不是某页最高匹配数已经证明订单归属。

**本轮未降低上述参数、未重写失败结果、未接入产品。** 后续应独立验证实际印刷区域、局部编号区域的几何支持与完整字符读取，而不是把缺少全页候选直接当作缺图，或根据已知答案放宽象限/跨度门槛。无论替代定位方法如何改进，物理编号完整性、字符歧义、打印修订/完整订单集合及正常场景的独立验收仍不可省略。
